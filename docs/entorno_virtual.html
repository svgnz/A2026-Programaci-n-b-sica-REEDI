Un proyecto, un entorno: venv, pip y requirements.txt

Objetivo de aprendizaje

Aplicar los comandos de venv y pip para crear, activar y usar un entorno virtual en un proyecto de Python, registrar sus dependencias en requirements.txt y reproducir el proyecto en otra computadora, diagnosticando los errores más comunes del proceso.

Dra. Perla Marlene Viera González · Dr. Guillermo Ezequiel Sanchez Guerrero · Dr. Yazmany Jahaziel Guerrero Ceja · Mtro. Osvaldo Habib González González

Elige tu sistema operativo arriba; los comandos se adaptan en todo el recurso.

Idea clave 1

¿Qué es un entorno virtual?

Una carpeta independiente con su propio intérprete de Python (copia o enlace del instalado) y su propio espacio para las bibliotecas de un proyecto, sin mezclarlas con las de otros proyectos ni con las del sistema.

Ejemplo

Un proyecto puede usar la versión 0.9 de una biblioteca mientras otro necesita la 0.10, sin que se afecten entre sí.

Ventajas

  • Evita conflictos entre versiones de bibliotecas.
  • Mantiene separadas las dependencias de cada proyecto.
  • Facilita reproducir el proyecto en otra computadora con requirements.txt.
  • No "ensucia" la instalación principal de Python.
  • Si algo falla, el entorno se borra y se vuelve a crear.

Conceptos clave

venv
Módulo incluido en Python que crea entornos virtuales. En Debian/Ubuntu puede requerir sudo apt install python3-venv.
pip
Herramienta que instala paquetes desde PyPI (pypi.org).
Paquete
Código reutilizable creado por terceros (biblioteca).
Dependencia
Paquete que un proyecto necesita para funcionar.
requirements.txt
Archivo de texto con las dependencias del proyecto y sus versiones.

Idea clave 2

Verificar Python, crear la carpeta y el entorno

En Windows, los comandos se escriben en el Símbolo del sistema (CMD): tecla Windows, escribir "cmd" y Enter.En macOS y Linux, los comandos se escriben en la aplicación Terminal.

1. Verificar Python

python --version      o bien   py --version
python3 --version

Debe mostrar algo como Python 3.13.x. Si "python" abre la Microsoft Store o no se reconoce, usa py o reinstala marcando "Add python.exe to PATH".El comando suele ser python3; con el entorno activado, python ya funciona.

2. Crear la carpeta del proyecto

mkdir reporte_calificaciones
cd reporte_calificaciones

mkdir crea la carpeta y cd la establece como ubicación de trabajo. Usa nombres sin espacios ni acentos.

3. Crear el entorno virtual

python -m venv .venv      (o  py -m venv .venv)
python3 -m venv .venv
python
python3
Ejecuta el intérprete de Python.
-m venv
Ejecuta el módulo venv como programa.
.venv
Carpeta donde se crea el entorno. El punto es una convención de elemento auxiliar; además la oculta al listar. VS Code la detecta con ese nombre.

Se crea una sola vez por proyecto y no muestra mensajes si todo sale bien. No guardes archivos del proyecto dentro de .venv.

.venv/
├── Scripts/    intérprete, pip y activación
├── Lib/        bibliotecas (site-packages)
└── pyvenv.cfg  configuración del entorno
.venv/
├── bin/        intérprete, pip y activación
├── lib/        bibliotecas (site-packages)
└── pyvenv.cfg  configuración del entorno

Idea clave 3

Activar el entorno e instalar con pip

Activar, verificar y desactivar

.venv\Scripts\activate.bat     # activar (CMD)
where python                   # verificar
deactivate                     # desactivar
source .venv/bin/activate      # activar
which python                   # verificar
deactivate                     # desactivar

Al activarlo aparece (.venv) al inicio de la línea, y la primera ruta de wherewhich debe estar dentro de .venv.

  • Activa el entorno antes de instalar o ejecutar.
  • La activación dura mientras esa terminal esté abierta; en una terminal nueva hay que activarlo otra vez.
  • Sin activar, se puede usar su intérprete directo: .venv\Scripts\python.exe main.py.venv/bin/python main.py

Instalar bibliotecas (entorno activado)

python -m pip install tabulate colorama

tabulate muestra listas como tabla; colorama muestra texto de colores. pip las descarga de PyPI (requiere Internet) y las instala dentro de .venv.

¿Por qué python -m pip? Si hay varias instalaciones de Python, el comando pip podría pertenecer a otra. python -m pip usa el pip del mismo intérprete que ejecutará el programa.

El aviso "A new release of pip is available" es solo informativo.

Idea clave 4

El programa del proyecto: main.py

Se crea dentro de reporte_calificaciones, no dentro de .venv.

from colorama import init, Fore, Style
from tabulate import tabulate

init()

calificaciones = [
    ["Ana", 95],
    ["Luis", 82],
    ["Sofía", 68],
]

print(Fore.GREEN + "Reporte de calificaciones" + Style.RESET_ALL)
print(tabulate(calificaciones,
               headers=["Nombre", "Calificación"],
               tablefmt="grid"))
init()
Prepara la terminal para colores (necesario en algunas versiones de Windows).
Fore.GREEN
Cambia el texto a verde; Style.RESET_ALL regresa al color normal.
tabulate()
Convierte la lista en una tabla con encabezados.

Ejecutar (entorno activado, en la carpeta del proyecto)

python main.py
Reporte de calificaciones +----------+----------------+ | Nombre | Calificación | +==========+================+ | Ana | 95 | +----------+----------------+ | Luis | 82 | +----------+----------------+ | Sofía | 68 | +----------+----------------+

Si usas VS Code

  1. Archivo > Abrir carpeta: reporte_calificaciones.
  2. Ctrl+Shift+P (Cmd+Shift+P) > "Python: Select Interpreter".
  3. Elegir el intérprete dentro de .venv.
  4. En la terminal de VS Code, en la flecha junto a "+", elegir "Command Prompt".
  5. Las terminales nuevas activarán el entorno automáticamente.
Actividad 3 · Revelar respuesta

Ayer Ana instaló tabulate y colorama en el entorno y el programa funcionó. Hoy abrió una terminal nueva, entró a la carpeta del proyecto y escribió python main.py. Obtuvo este error. ¿Qué ocurrió y cómo se corrige?

ModuleNotFoundError: No module named 'colorama'

Qué ocurrió: la activación solo dura mientras la terminal está abierta. En la terminal nueva se ejecutó el Python del sistema, que no tiene las bibliotecas; estas siguen instaladas dentro de .venv.

Corrección: activar de nuevo el entorno y luego ejecutar. No hace falta reinstalar.

.venv\Scripts\activate.bat
python main.py
source .venv/bin/activate
python main.py

Idea clave 6

requirements.txt: la lista de ingredientes

Generarlo con pip freeze

python -m pip freeze > requirements.txt

freeze lista los paquetes del entorno con su versión exacta y > la redirige a un archivo. Incluye también las dependencias que se instalaron automáticamente. Vuelve a ejecutarlo cada vez que instales o desinstales una biblioteca.

Escribirlo a mano

# Bibliotecas del proyecto reporte_calificaciones
tabulate==0.10.0
colorama>=0.4.6

Una biblioteca por línea; # inicia comentarios; las líneas en blanco se ignoran; no importan mayúsculas o minúsculas. Para esta clase se recomienda ==.

Comando de cada paso

  • Paso 1 · Se recibe la carpeta del proyecto, sin .venv.
  • Paso 2 · cd reporte_calificaciones
  • Paso 3 · Revisar que el archivo esté en la carpeta (por ejemplo, listando su contenido).
  • Paso 4 · Sin el archivo, pip mostraría ERROR: Could not open requirements file.
  • Paso 5 · El archivo existe: se continúa con la preparación.
  • Paso 6 · python -m venv .venvpython3 -m venv .venv
  • Paso 7 · .venv\Scripts\activate.batsource .venv/bin/activate
  • Paso 8 · python -m pip install -r requirements.txt: -r indica que lea la lista desde el archivo. Se comprueba con python -m pip list.
  • Paso 9 · python main.py
  • Paso 10 · deactivate
  • Paso 11 · Termina la decisión del paso 3.
  • Paso 12 · Fin: el proyecto funciona en la nueva computadora.

Recibir→Crear entorno→Activar→pip install -r→Ejecutar
