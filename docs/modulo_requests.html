Idea clave 1

¿Qué es requests?

Una biblioteca que envía solicitudes HTTP a servidores para consultar, enviar, modificar o eliminar información. Se usa con frecuencia para consumir API y recibir datos en formato JSON.

A diferencia de os y re, hay que instalarla

No es parte de la biblioteca estándar. Se instala desde la terminal, no desde el intérprete de Python (>>>):

python -m pip install requests      # general
py -m pip install requests          # Windows
python3 -m pip install requests     # macOS/Linux
python -m pip show requests         # verificar

Luego, en el programa: import requests. Si no está instalada: ModuleNotFoundError: No module named 'requests'.

Conceptos previos

API
Reglas que permiten a un programa solicitar datos o servicios a otro. Una API web se consulta mediante URL.
HTTP
Protocolo de comunicación entre un cliente (nuestro programa) y un servidor: solicitud → respuesta.
Endpoint
URL específica de la API que entrega un recurso.
Programa (cliente)→ solicitud GET →Servidor de la API→ respuesta →status_code + JSON

Idea clave 3

Métodos HTTP y códigos de estado

Métodos más comunes

GET · get()
Consultar información. Es el enfoque de este recurso.
POST · post()
Enviar información para crear un recurso u operar.
PUT · put()
Reemplazar un recurso existente.
PATCH · patch()
Modificar parcialmente un recurso.
DELETE · delete()
Solicitar la eliminación de un recurso.

Familias de códigos

2xx
Éxito: 200 OK, 201 Created.
3xx
Redirección: el recurso está en otra dirección.
4xx
Error de nuestra solicitud: 400, 401, 403, 404, 429.
5xx
Error del servidor: 500, 503.

Idea clave 4

  
La solicitud y el objeto Response

  

    

      
requests.get(url, params=..., headers=..., timeout=...)

      

        
params
Diccionario de parámetros de búsqueda; requests los agrega a la URL y codifica espacios y acentos.

        
headers
Diccionario de cabeceras, por ejemplo de autenticación.

        
timeout
Segundos máximos de espera: 10 o (3, 10) para conexión y lectura. Sin él, puede esperar indefinidamente.

      

      
url = "https://jsonplaceholder.typicode.com/posts"
parametros = {"userId": 1}
respuesta = requests.get(url, params=parametros, timeout=10)
print(respuesta.url)
# https://jsonplaceholder.typicode.com/posts?userId=1

    

    

      
Lo que trae la respuesta

      

        
.status_code
Código de estado HTTP (int).

        
.ok
True si el código es menor a 400.

        
.json()
Convierte el JSON en datos de Python (dict o list).

        
.text
Contenido como texto (str).

        
.content
Contenido en bytes: imágenes, PDF, otros archivos.

        
.headers
Cabeceras de la respuesta (similar a un diccionario).

        
.url
URL final consultada, con parámetros.

        
.raise_for_status()
Genera HTTPError si el código es 4xx o 5xx; si no, no hace nada.

      

    

  

  

    Actividad 3 · Revelar respuesta
    
La solicitud se atiende con código 200 y su contenido es el JSON del usuario 1. Aun así, la última línea falla. ¿Qué error se produce, por qué y cómo se corrige?

    
respuesta = requests.get("https://jsonplaceholder.typicode.com/users/1", timeout=10)
respuesta.raise_for_status()
datos = respuesta.text
print(datos["name"])

    

    

      
Error: TypeError: string indices must be integers.

      
Por qué: respuesta.text es una cadena (str) con el JSON tal como llega; a una cadena no se le puede pedir la clave ["name"].

      
Corrección: convertir con json(), con paréntesis; respuesta.json sin ellos devuelve el método, no los datos.

      
datos = respuesta.json()

Idea clave 7

  
Manejo de errores: el orden de los except importa

  

    

      
try:
    respuesta = requests.get(url, timeout=10)
    respuesta.raise_for_status()
    datos = respuesta.json()
    print(datos["name"])
except requests.exceptions.Timeout:
    print("La solicitud tardó demasiado.")
except requests.exceptions.ConnectionError:
    print("No hay conexión con el servidor.")
except requests.exceptions.HTTPError:
    print("La API devolvió un error HTTP:", respuesta.status_code)
except requests.exceptions.JSONDecodeError:
    print("La respuesta no contiene JSON válido.")
except requests.exceptions.RequestException:
    print("No fue posible realizar la consulta.")
except KeyError:
    print("La respuesta no contiene el dato esperado.")

    

    

      
Jerarquía simplificada

      
RequestException
├── ConnectionError
├── Timeout
├── HTTPError
└── JSONDecodeError  (también es ValueError)

      
Python usa el primer except que coincide. RequestException es la general: va al final del grupo. ConnectTimeout es a la vez Timeout y ConnectionError; por eso Timeout va antes.

    

  

  

    
ModuleNotFoundErrorLa biblioteca no está instalada.

    
pip en >>>pip install es un comando de terminal.

    
Archivo requests.pyPython importa tu archivo: module 'requests' has no attribute 'get'.

    
Sin timeoutEl programa puede quedarse esperando sin fin.

    
json sin ( )Se obtiene el método, no los datos.

    
KeyErrorClave mal escrita o inexistente; distinguen mayúsculas.

    
TypeErrordatos["name"] sobre una lista; usa datos[0]["name"].

    
API_KEY expuestaNunca en el código: usa variables de entorno.

Resumen

  
Lo esencial de requests

  

    
Enviar
requests.get(url, params=..., timeout=10). Instálala antes con pip desde la terminal.

    
Verificar
raise_for_status() o status_code: un 4xx o 5xx no genera excepción por sí solo.

    
Procesar
respuesta.json() da dict o list; accede con claves e índices, o con get().

    
Prevenir
try/except de lo específico a lo general; la API_KEY, en variables de entorno.
